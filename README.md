# WhyNot

**当你不知道接下来做什么，WhyNot 给你一个现在就能开始的建议。**

走在路上、一个人吃饭，或刚上完一节课时，我们常常顺手打开抖音。有时是真的想看，有时只是暂时想不到别的选择。WhyNot 是一个 AI 生活伙伴，帮你在这些空当里，刷视频之前选一件适合当下的事。做件小事、看看周围或者什么都不做，都可以。

## 一次推荐是什么样的

你刚下课，在食堂等饭，还有 10 分钟，脑子有点累。打开 WhyNot，选好时间和状态，点「出一张现在」随机开始互动。下面是这次抽到小行动时的一条建议示例：

> 等饭的时候，给自己两分钟放空。把手机放在桌上，看看窗外。饭到了就安心吃。

如果这条建议不合适，点一下「换一个」（完成后显示「换一张」）。想自己决定，直接关掉也行。

| 此刻的情境 | WhyNot 可能给出的建议 |
| --- | --- |
| 在食堂吃饭，还有几分钟，想看点新鲜的 | 看看窗口是怎么分开点单和取餐的。你能找到一个让队伍走得更快的设计吗？ |
| 有 3 分钟，想看看日常技术的小细节 | 看一张二维码，找找三个方形定位标记。二维码还会存一些冗余信息，所以局部被挡住时，扫描器有时仍能恢复原来的内容。 |
| 忙完一阵，想轻松一下 | 想刷短视频就刷一会儿。要是 10 分钟后还有事，可以先定个提醒。 |

## 当前 P0 怎么用

项目已有可在本地运行的前后端，不再只是产品构想。当前界面为「此刻车票 V3」，主页面只有「此刻」，没有「今日」页或历史列表；页脚折叠区为「关于与数据」，包含主题、数据说明及记忆管理。

- 默认 **10 分钟、还可以（steady）**，场景可跳过。时间可选 3／5／10／15 分钟，精力可选有点累／还可以／精神好；场景为等饭／排队、在桌前、在路上、在家／宿舍。
- 主按钮可见文字保持 **「出一张现在」**，无障碍名称为「出一张现在，开始一次互动」，实际调用 `startInteraction`，不是退回仅推荐。按当前条件随机开场，保留聊聊／讨论（多轮文字）、小行动（`micro`）和看图学词（上传照片识别一个英文词）。首次成功后收起三行引导；存储受限时不能跨刷新记住收起状态。
- 小行动每次给一条建议，写清第一步和预计耗时，耗时不超过所选预算；小行动及互动存储不可用（503）后选择降级的普通推荐，都使用完整 V3 票卡、时长刻度、完成盖章与分享流程。503 时先说明原因，不悄悄掩盖互动不可用。
- 非 `micro` 互动保留对话卡：聊聊／讨论可连续多轮，「结束互动」收起输入；看图先上传照片得到词卡（英文／音标／释义／练习），歧义时先问再澄清或重拍。结束聊天不等于完成一条建议，不宣称所有聊天都有完成印章或分享入口。
- 修改条件不会自动生成。「换一个／换一张」使用**当前表单**条件：当前为互动时携带 `replaces` 重开并排除上一方式，普通建议则调用推荐端点；均不提交 `swap` 或其他反馈。失败后的「再试一次」保留**失败请求的条件快照**，互动重试复用同一 UUID（`request_id`），不会悄悄改用新条件；请求冲突或替换对象已不存在时按提示重新开始，而非无限重放。
- 建议卡的「喜欢」「不喜欢」只在完成前互斥改选，以最后选择为准。完成记录独立、幂等，确认成功后不可撤销；完成后偏好仅保留装饰状态，不再可改选。反馈始终绑定具体建议，小行动反馈不丢失互动状态。
- 聊天中的候选记忆可以「保存」「改一下再保存」或「跳过」，只有确认保存后才成为记忆；在「关于与数据」的「我让 WhyNot 记住的事」中可查看、编辑、删除。该折叠入口的无障碍名称也包含记忆管理。

建议参考主动选择的时间、精力、场景和当前匿名会话的历史偏好；互动还按功能使用对话、主动上传的图片及用户确认保存的记忆。不提供兴趣输入，也不接入或追踪定位、日历、健康与兴趣数据。累了可以休息，有点好奇心时也可以探索身边的小事。推荐与小行动在未配置模型密钥或模型失败时可使用符合条件的内置建议；这不代表自由聊天或看图识别也能无模型完成。模型调用每次超时 7 秒，最多尝试 2 次，并校验输出；对话／识别失败须明确提示并保留可重试状态。

## 此刻车票 V3 界面与边界

界面采用「此刻车票 V3」视觉体系，保留系统字体、原生 HTML／CSS／JavaScript，无新增前端运行时依赖。[原始 V3 方案](deliverables/now-pass-v3/00-plan/WhyNot前端方案-此刻车票V3.docx) 保留为设计参考。小行动与普通推荐的建议卡带主题票头、五类类别文字及对应几何图形、时长刻度；装饰编号不替代 API `id`。非 `micro` 互动沿用远端对话卡，不把建议卡的完成态套到所有聊天上。

- 页脚折叠的「关于与数据」说明匿名会话、推荐、反馈、对话、图片与记忆的数据用途，提供记忆查看／编辑／删除及跟随系统／浅色／深色主题。页面默认跟随系统，按已保存偏好设置页面 `theme-color` meta。显式 `light`／`dark` 选择存于 `whynot-theme`，跟随系统则移除覆盖值；存储读写失败时静默回到跟随系统。
- 小行动与普通推荐点击「已完成」先乐观呈现完成印章与完成布局，确认失败则回滚；只有服务端确认成功后才允许「分享此刻」，请求中或失败时禁止分享。完成后操作区只保留「已完成」状态、「换一张」和「分享此刻」，偏好仅作装饰。分享降级顺序为原生分享 → Clipboard → `execCommand` → 可选中文本手动复制。用户取消原生分享时安静结束，不再复制。分享链接只取 `location.origin + location.pathname`，不带 query、hash、建议编号、会话或反馈信息；分享不会记录反馈。
- 安装资源采用三笔抽象锁齿票标：SVG favicon 和 Apple 180px、192／512px PNG 均为 `#101827` 夜色底／`#F6F2E8` 米白图形。PNG 不透明，manifest 图标 `purpose: "any"`，不声明 maskable；manifest 启动 `background_color`／`theme_color` 固定为 `#101827`，不随用户主题动态变化。可在仓库根目录用 `node dev/generate-icons.mjs` 无额外依赖地重复生成图标。资源检查不等于原生安装验收，能否添加到主屏幕取决于浏览器，不承诺自动安装。
- **无 service worker，不支持离线重新打开。** 已打开的页面断网后仍可看原卡片，但不能生成新建议；恢复网络后由用户手动重试。

## 本地使用

在项目目录运行 `npm start`，打开 **http://127.0.0.1:8787/**；按 Ctrl+C 停止。使用 Node.js 22.9 或更新版本，首次运行先执行 `npm ci`。无需云数据库，不会修改或发布线上站点。

- 数据保存在 `.local/data/`，重启会保留；启动时自动执行尚未应用的数据库迁移。同一数据库只能启动一个服务。备份时先停止服务，再复制整个数据目录。
- 在项目根目录 `.env` 中设置 `MODEL_API_KEY=你的DeepSeek密钥`，`MODEL_ENDPOINT=https://api.deepseek.com/chat/completions`，保存后重启服务。密钥只在服务端读取，`.env` 和 `.local/` 已被 Git 忽略；不要把密钥发到聊天或提交到仓库。
- 不配置密钥也能生成内置建议，在「聊聊」模式发送「帮我记住：……」并确认保存、查看、修改或删除记忆；自由聊天、模型生成与看图识别需要有效密钥。页面显示「已配置」只代表读到了配置，不代表模型服务验证通过。
- 保留远端的 DeepSeek 调用修复：服务端默认端点为上述地址，模型为 `deepseek-flash`；统一 JSON 输出、将多轮 assistant 历史编码为 JSON，并关闭思考模式。修复不放宽 7 秒／最多 2 次的调用限制，不跳过输出校验，也不保证网络、其他模型服务或每次请求都成功；失败仍提示并允许重试。本次合并后的真实模型结果须另行实测，不能沿用远端历史成功作当前结论。
- 固定使用上述地址和同一浏览器；匿名会话保存在浏览器，清除浏览器数据或换端口会失去旧会话入口，但不会删除数据库。记忆和对话仍遵守原有有效期与清理规则，不是永久保存。
- 本地使用模式只监听本机，禁用 `/__local/*` 测试控制接口。`npm run test:local` 使用独立临时数据库验证重启保留、记忆操作及安全边界，不触碰使用数据，也不调用真实模型。

## 当前 API 契约

代码入口为 `functions/index.ts` → `functions/routes.mjs`；浏览器统一基址为 **`/functions/v1/app`**。以下路径均接在该基址后：

| 方法与路径 | 行为 |
| --- | --- |
| `POST /api/session` | 建立匿名会话，返回 `{ok:true, token}`；已有有效 token 时复用，返回 `{ok:true}`。 |
| `POST /api/recommendations` | JSON 条件生成一条建议，成功为 201。 |
| `POST /api/recommendations/:id/feedback` | JSON `{kind:"like"}`／`dislike`／`completed`，成功为 200 并返回更新后的卡片。 |
| `GET /api/health` | 健康检查，返回 `{ok:true}`。 |
| `POST /api/interactions` | 开始一次随机互动，返回开场白与可聊话题。 |
| `DELETE /api/interactions/:id` | 结束互动，成功为 204。 |
| `POST /api/interactions/:id/turns` | 追加一轮对话，可能返回词卡或回忆。 |
| `POST /api/interactions/:id/images` | 上传一张照片作为识别候选，上限 4 MiB。 |
| `POST /api/interactions/:id/memories` | 确认（可先修改）或跳过候选记忆，未确认不保存。 |
| `GET /api/memories` | 列出当前会话的记忆。 |
| `PATCH`／`DELETE /api/memories/:id` | 修改或删除一条记忆。 |

推荐与反馈之外，互动、图片与记忆端点依赖直连 PostgreSQL（`WHYNOT_DATABASE_URL`）；未配置时这些入口返回 503 `STORAGE_UNAVAILABLE`，推荐与反馈不受影响。当前 Functions **没有 `/api/history`**。

会话流程：前端把 token 存于 `localStorage` 的 `whynot-session`，后续通过 `x-whynot-session` 请求头携带；存储不可用时仍可在当前页面内存中使用。服务端按 token 的 SHA-256 摘要识别归属，不信任请求 JSON 中的用户身份。前端保留 `credentials: 'same-origin'`，但 Sites 网关不转发应用 cookie，当前路由不靠 cookie 认证。

推荐请求只接受 `budget`（整数 3／5／10／15）、`energy`（`low`／`steady`／`high`）及可省略或为 `null` 的 `scene`（`waiting`／`desk`／`outside`／`home`），拒绝额外字段。例如：

```json
{"budget":10,"energy":"steady","scene":null}
```

卡片字段为 `id`、`scene`、`energy`、`budget`、`category`、`title`、`first_step`、`detail`、`minutes`、`created`、`preference`、`completed`。增量字段 `category` 取 `rest`／`observe`／`listen`／`tidy`／`explore`；缺失、空值或未知值时前端仅隐藏类别，不丢弃整卡。`preference` 为 `null`／`like`／`dislike`，`completed` 为布尔值。普通建议换卡调用推荐端点；当前为互动（含小行动）时，携带 `replaces` 调用互动开场端点，没有 `swap` 反馈类型。

互动开场除条件外携带 `supports` 和 UUID `request_id`，换互动时增加 `replaces`。重试保留原条件和同一 `request_id`；续聊使用对应的互动版本与请求编号，防止重复提交或迟到响应覆盖新状态。

推荐与反馈的典型错误：401 `SESSION_REQUIRED`，400 `INVALID_CONTEXT`／`INVALID_FEEDBACK`／`INVALID_BODY`，415 `JSON_REQUIRED`，404 `NOT_FOUND`（含不属于当前会话的建议），503 `STORAGE_UNAVAILABLE`；其 JSON 请求体超过 2048 字节返回 413 `INVALID_BODY`。互动、图片与记忆另有各自的输入、版本和归属校验，不能把该 JSON 上限当作照片上传上限。

`app.py` 是较早的 Python／SQLite 原型：访问首页设置 HttpOnly `whynot` cookie，直接使用 `/api/*`，另有 `GET /api/history`。它与当前共享前端的 `/functions/v1/app` URL 和 token 会话流不兼容，不能用 `python app.py` 替代上述当前前端联调入口。

## 后端发布配置

1. 在同一 PostgreSQL 数据库中保留或迁移现有 `app` 数据。全新数据库先创建 `app` schema 再应用 `schema.sql`，然后按编号应用尚未执行的迁移。新版互动使用支持事务的直连 PostgreSQL。使用服务端密钥 `WHYNOT_DATABASE_URL` 配置运行时连接；若连接角色和迁移角色不同，向运行角色授予所需表、序列及 `app.clear_interaction`、`app.redact_invalid_memory_turns` 的访问权限。未配置该连接时，原推荐和反馈继续使用托管数据库客户端，互动入口返回存储不可用。
2. 在同库启用 `pg_cron` 后，由迁移角色运行 `ops/schedule-cleanup.sql`；也可以使用现有数据库调度器每五分钟执行 `SELECT app.purge_expired()`。清理在无访客时也会执行。
3. 运行 `npm run build:function`，将生成的 `.local/function` 作为 Function 源目录。目录包含入口和解码所需的 WASM。托管平台在发布时提供 `_qoder/backend.mjs`。在 Function 环境中配置模型密钥后即可开启模型开场和图片识别。
