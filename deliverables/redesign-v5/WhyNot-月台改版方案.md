> 视觉：frontend-design-architect｜体验：ux-ui-designer｜工程：frontend-engineer｜汇编：主理人

## 一句话

把「三站盖章」改成**一张被当场填写的票**：月台铺满整个视口，右侧一张空白票有三道横线；答一格，它就收成一行印刷体，再展开下一格；三格填完，票从出票口推出来。

三个诉求对应三个动作：

| 诉求 | 做法 | 结果 |
| --- | --- | --- |
| 极简操作盘面 | 一屏一问：答完一格收成一行，下一格才展开 | 每屏只做一次判断；首次 3 步，回访「用上次的条件」1 次点击 |
| 动态美术画面 | 16:9 月台铺满 100svh + 列车进站 + 光锥 + 湿地面倒影 | 网页级全屏冲击力；浅色换清晨底图，火车依然看得见 |
| 「现在」的车票 | 站台号 / 车次 / 区间 / 刻度 / 票根 / 印章 | 一张信息完整的真票，而不是一张建议卡 |

## 1. 现状诊断

详见 [00-现状诊断.md](00-现状诊断.md)。三条关键事实：

1. **操作成本**：三站逐屏，每站一张大票 + 4 个竖排按钮，选中后要走 盖章 120ms → 撕票根 360ms → 收根 200ms → 换站 200ms，三站合计约 **2.6 秒**，改一次条件必须走完。
2. **视觉**：票券细节（齿孔、虚线撕口、竖排票根、印章）已经成熟，但页面除这张纸之外是纯色底，没有场景，视觉张力全压在一张纸上。
3. **信息**：结果卡说的是「一条建议」，不是「一张行程」。缺站台、车次、区间这些能让「现在」变成一段具体时间的符号。

## 2. 五个设计决定

这五条决定了后面所有数值，先列出来，避免执行时被局部优化带偏。

### 决定一：票既是表单，也是结果

填写时它是一张有三道横线的空白票，出票后它变成一张印满字的票——**同一个容器、同一齿孔、同一票头基线**，只是内部区块换了。用户感知是「这张票填完了」，不是「表单提交后弹出一张卡」。

### 决定二：一次只问一件事，但已答的必须留在眼前

整屏只有一个问题，选项 48px 高。答完这一格立刻收成一行印刷体（`10 分钟` + 改），下一格才展开。这样既没有「三组同时在场」的扫视负担，也不会让人忘记自己前面选了什么。

代价是首次多点两下，用两条补：场景第一步是「跳过」；回访用户「用上次的条件」一键填满。

### 决定三：场景是物理空间，不是背景图

票从站台中央的售票机出来，落在站台面上；黄线永远在票的**下方且不被遮挡**——它是「你站在站台边」的唯一地面证据。车头灯在右，所以票的受光边是右缘与顶缘，投影落向左下。

### 决定四：仪式只保留一次，放在出票那一刻

三站逐屏的三次撕裂取消，只在出票时保留一次完整的机械动作：主按钮下压 480ms → 票头从出票口露出 → 票落定 1240ms。换一张**不重放列车进站**，只闪一次车窗灯。

### 决定五：失败与降级都不夺走用户的条件

出票失败显示「这次没出票」，条件全保留、盘面可编辑、重试复用同一份条件快照；存储 503 降级为普通推荐时，票头下加一条灰条「本次不保存记录」，功能照常。

## 3. 填票流程（一屏一问）

### 3.1 为什么从「一屏三行」改成「一屏一行」

第一版把三组选择压进一张 358 宽的票里，本质是**手机思维**：屏幕窄，只能把东西竖着叠。但这是个网页，桌面有 1000px 以上的横向空间，没必要把三组塞进一列。

一屏三行的代价也很实在：三组同时在场，**没有主次**，用户要横着扫三遍才能确认自己选了什么；窄屏还得为「每格 ≥44px」去抠 gap 和 padding，最后靠竖排侧标才勉强成立。

一屏一行把这件事变简单：整屏只问一个问题，选项 48px 高、两列排开，眼睛只做一次判断；答完这一格**收成一行印刷体**，下一格才展开。它不是表单分步，而是**一张票从上往下被填写**——填过的地方变成已打印的字，没填的地方是一道空横线。

代价要说清楚：首次使用要多点两下（3 次选择 + 1 次出票）。用两个办法补：

- 场景那一步的「跳过」放在第一位，不想选就点第一格；
- 回访用户点「用上次的条件」，三格一次填满，直接出票（1 次点击）。

### 3.3 四个状态

| --- | --- | --- | --- | --- |

| 印章 | Ø64 / right 56 / bottom 80，仅在结果票出现 |

### 3.5 浅色不是「把夜色提亮」

第一版浅色是把夜景图加一层米白幕，结果火车被洗成一片雾——这是「同一张图调亮度」的通病：提亮会让暗部发灰，车体和站台糊在一起。

改成**换一张图**：昼 / 夜两张 16:9 同构图底图，切主题时 700ms 交叉淡入。

- 夜班：`#0d1526 → #1b2740`，车灯是唯一光源。
- 清晨：`#cfe0f2 → #f4efe2`，低角度阳光，列车在右侧逆光，仍然清晰。
- 遮罩：左侧 0.86 → 60% 处 0.16 → 右侧 0.26，只压文字区，不压列车；浅色下给底图 `contrast(1.06) saturate(1.06)`。
- 票面在两套主题里都不变，只换阴影强度。

### 3.6 响应式

| 视口 | 布局 | 票宽 | 选项 |
| --- | --- | --- | --- |
| 1440+ | 左文右票，场景满屏 | 460 | 2 列（场景 3 列） |
| 1100–1439 | 同上，间距收窄 | 420 | 2 列 |
| 768–1099 | 单列：票在文案下 | 460 | 2 列 |
| ≤767 | 单列，场景仍 100svh | 100% − 40 | 2 列 |

窄屏不退回「三组挤一屏」，只把左右改上下、把选项改单列。

### 3.7 键盘与读屏

- 每一格是一个 `radiogroup`，方向键在组内移动并即时选中，`Home/End` 跳首尾。
- 选中后焦点**移到下一格的第一个选项**，而不是回到页顶；最后一格选完，焦点落到主按钮。
- 单播报节点播「已记下 10 分钟，下一步：精力」；出票只播一次「已出票」。
- 折叠动画在 `prefers-reduced-motion` 下改为即时显示，不做高度过渡。
- 「用上次的条件」是普通按钮，不是默认行为——不用它的人不会被替做决定。

## 4. 月台

### 4.1 资产策略：位图底 + 矢量动效

| 方案 | 美术上限 | 首屏 | 换主题 | 动画自由度 | 结论 |
| --- | --- | --- | --- | --- | --- |
| A 纯矢量多层 SVG | 中（湿地面、雾、金属质感偏假） | 最好 | 最好 | 高 | 备选 |
| **B 位图底 + SVG/CSS 叠加** | **高** | 中（2 张 AVIF） | 中 | 高 | **选它** |
| C Canvas 2D 实时 | 高但难控 | 差 | 差 | 最高 | 不选 |

理由：电影感的 80% 来自**静态光影与材质**（湿站台反光、雾的散射、金属菲涅尔），这是位图的强项；剩下 20%（列车位移、光锥扫过、浮尘、倒影抖动）必须可编程，这是位图的死穴。B 让两者各做擅长的部分。

底图只出 **2 张**（昼 / 夜，1920×1080 @1x，2560×1440 @2x，16:9 横构图，列车在右、左侧留白给文案）；黄昏由调色层生成：`filter: sepia(.35) saturate(1.3) hue-rotate(-12deg) brightness(1.15)` + 一层 `#ff8a50 @.18` 的 `soft-light`。**列车、光锥、浮尘、倒影、bloom 全部矢量**——它们是运动主体，位图位移会让 GPU 每帧上传大纹理。

**遮挡顺序（近→远）**：前景立柱 > 站台面与黄线 > 列车 > 售票机 > 轨道 > 灯柱 > 薄雾 > 站房 > 天。近景桁架横在画面顶部（y 110–152），不参与中景遮挡，只负责「你在雨棚下」。

列车从右进站，但只走 **148px** 就停稳——它从 38% 的画外驶入，大部分车身始终在画外。这既符合站台的真实尺度（车比站台长得多），也避免一大块深色穿过票面。车头灯在 x 72%、y 77%，光锥朝右下方，落在站台面上，不与票面文字区相交。

### 4.3 光模型

| 角色 | 色 | 强度 | 实现 |
| --- | --- | --- | --- |
| 主光 · 车头灯 | 3800K `#ffd9a0` | 峰值 .62 | 3 层 `conic-gradient(from 160deg at 72% 77%, …)` 张角 42°、长 260px，blur 18/36/72px，opacity .55/.28/.12，`screen` |
| 辅光 · 车窗溢光 | 3200K `#ffcf94` | .34 | 240×160 径向椭圆，blur 24px，贴 y=412 站台面，`screen` |
| 环境光 · 夜 | `#24304a` | 12% | 全场景 `multiply`，让暗部统一偏蓝 |
| 环境光 · 昼 | `#f2eee4` | 8% | `soft-light` |
| 湿站台反射 | 车身/车窗 `scaleY(-3.4)` 副本 | .28 | 近 blur 8px、远 blur 18px，`mask` 向下 70% 淡出 |

### 4.5 进站分镜（3200ms，与出票并行）

镜头整体 `scale(1→1.03)`，`transform-origin: 62% 74%`，全程 3200ms `cubic-bezier(.3,.2,.2,1)`，结束不回位。

| ---: | --- | --- | --- | ---: |
| 0 | 镜头 | scale 1→1.03 | (.3,.2,.2,1) | 3200 |
| 0 | 车头灯 bloom | opacity 0→.9，半径 24→96 | ease-out | 420 |
| 0 | 雨棚桁架（近景） | `translateX(-8px)` 缓慢漂移 | ease-out | 3200 |
| 0–180 | 城市灯带 / 站房 | 先动：`translateX(+6px)` 并淡 .2 | ease-out | 3200 |
| 120 | 光锥 | 从画外扫入，张角 0→42°，落点 (72%, 77%) 向右下 | (.22,.61,.24,1) | 1100 |
| 180 | 列车 | `translateX(148px → 0)` | (.22,.61,.24,1) | 1180 |
| 180 | 速度线 ×3 | opacity 0→.4→0 | linear | 700 |
| 300 | 浮尘 | 14 点错峰淡入（每点 +60ms） | ease-out | 500 |
| 900 | 前景立柱 | 后动：`translateX(-4px)` 反向 | ease-out | 900 |
| 1180 | 车门 | `scaleX(0→1)` | (.65,0,.35,1) | 350 |
| 1200 | 地面暖光 | 车门溢出 220×90 椭圆，opacity 0→.45 | ease-out | 600 |

关键：列车 1180ms 与出票时间轴**同时开始**，用户感知总时长 **1240ms**，不是 2640ms。

列车只走 148px，位移本身不足以产生速度感——速度感来自**光锥先扫过、近景桁架反向漂移、浮尘被推起**这三件事的错位。这也是为什么必须做多层视差，而不是让一张列车图平移。

### 4.6 静息收敛

`t = 20s` 加 `data-phase="resting"`：车门关闭 300ms → 车窗灯 opacity 1→.25（600ms）→ 只留头灯常亮 → 灯柱光晕与薄雾 `animation-play-state: paused`。此后**运动源数量为 0**。

原则：静息态是「车停好了，等你」，不是「还在演」。验收断言：`document.getAnimations().filter(a => a.playState === 'running').length === 0`。

### 4.7 三套氛围

| | 清晨 06–09 | 黄昏 17–19 | 夜班 20–06 |
| --- | --- | --- | --- |
| 天光 | `#cfe0f2 → #f6f1e2` | `#f7c98e → #c4735a → #5b4a6b` | `#0d1526 → #1b2740` |
| 站台面 | `#cfc8b8` | `#a8877a` | `#141d2e` |
| 灯光 | .45 | .65 | .9 |
| 雾 | .35 | .28 | .14 |

**场景跟时间，UI 跟主题**：场景按本地时间三选一（每 10 分钟检查一次），纸面、文字、按钮仍由系统深浅色决定。这样「夜里用浅色主题」不会跳到白天月台，纸台作为半透明介质天然是两者的过渡。设置里给「月台光线：自动 / 清晨 / 黄昏 / 夜班」，默认自动。

降级：只做**昼 / 夜两张底图**，黄昏由调色层生成。三套是「更好」，两套是「够用且够稳」——建议先上两套。

## 5. 车票

### 5.1 版式（桌面 460 × 366，票身 294 + 票根 72）

### 5.3 验票撕票根（520ms）

撕票挂在「已完成」上——出票是「拿到票」，验票是「票被使用」，两件事不能合并。

| t (ms) | 动作 |
| ---: | --- |
| 0–120 | 撕口自左向右生长（`mask-size` 0→100%，近匀速） |
| 120–240 | 票根 `rotate(−2°)` + 下移，投影出现 |
| 240–520 | 票根抬起 `−7°` 后向右下 `(96, 54)`、`rotate(6°)`、淡出离开；同段票根高度 72→0，票身高度 366→294 |
| 520 | 定格：票身底边留撕口毛边，按钮第三颗变「换一张」，下方写「已验 · 15:42」，播报一次 |
| 600–860 | 只有结果票：印章落下（表单票不落章） |

实现约束：只动 `transform / opacity / height`；用 520ms 定时器推进状态，不依赖 `animationend`；票根撕完 `visibility:hidden` 退出无障碍树；`prefers-reduced-motion` 下 120ms 交叉、无位移。变量只有六个：`--body-h / --stub-h / --ticket-h / --bar-w / --vx / --vy`。

### 5.4 票与景的三条物理关系

1. **出票口是唇光不是洞**：售票机在 x 135–255，票口 96×10 在 y 420。真正的出票内腔宽 358、深 12px，藏在 y 412–424 的暗带里；中央 96 宽是唯一透光的唇口。票下落时先遮住唇光，唇光被「吃掉」逐渐收窄到 0。这既解释了「96 宽的洞怎么吐 358 宽的票」，又给了「撕开一道光的缝」这个记忆点。
2. **受光边**：车头灯在右（x=310），票的右缘与顶缘受光（`rgba(255,217,160,.55)`），左缘与下缘为暗边；投影落向左下（`-18px 22px 30px rgba(0,0,0,.32)`）。这个反常规的投影方向是「光从右边来」的唯一证据。
3. **黄线不可遮**：黄线在票的上方、始终可见。任何视口、任何状态，票都不允许盖住这条线——被遮掉，画面就失去纵深。

### 5.5 印章落地

落印 60ms 后，一个 `.42` 不透明度的复本「投」到站台地面（y 462，`scaleY(-.6)`），2s 内淡到 .28 并恒存。票被换掉时地面印记不消失，累积成「今天盖过几枚」的浅痕（最多 5 枚，超出则最旧一枚先淡出）。印章因此是**场景里**的东西，不是票上的贴纸。

## 6. 动效语言

| token | 值 | 语义 |
| --- | --- | --- |
| `--m-quick` | 120ms `cubic-bezier(.2,0,.2,1)` | 按下、选中、焦点 |
| `--m-soft` | 220ms `cubic-bezier(.33,1,.68,1)` | 纸面淡入、面板展开 |
| `--m-ticket` | 380ms `cubic-bezier(.16,1,.3,1)` | 纸：先快后长尾，末端停住，无回弹 |
| `--m-mech` | 480ms `cubic-bezier(.65,0,.35,1)` | 机械：对称、恒速中段 |
| `--m-train` | 1180ms `cubic-bezier(.22,.61,.24,1)` | 进站减速 |

**纸 = 长尾 + 零过冲（<2%）；机械 = 对称 + 无过冲 + 中段恒速。** 禁止 spring 回弹、禁止线性（除条形码花纹）。

| 动效 | 参数 |
| --- | --- |
| 出票 | 550ms `--m-ticket`；`translateY 28→0` + `opacity 0→1` + `rotate -1.2deg→0` |
| 撕票根 | 380ms；票根 `rotate 0→-7deg` + `translate(-14,6)` + `opacity 1→0`；票身宽度同步 88→0（必须同为 380ms，否则「根没撕完洞就合上」） |
| 盖章 | 260ms `(.5,0,.3,1.4)` + 60ms 后 `scale(1.06)→1` 90ms；起手 `scale(1.8) opacity 0` |
| 换票 | 旧票 380ms 撕离，新票延迟 120ms 落定；列车不重放，只闪一次车窗灯 200ms |

## 7. 无障碍与降级

| 场景 | 用户看到 |
| --- | --- |
| `prefers-reduced-motion` | 无进站、无盖章旋转、无票推出；状态切换 120ms 交叉；主按钮用 1px 位移代替下压。功能与播报完全不变。 |
| 位图加载失败 | 场景退化为纯 CSS 渐变分层（8 层本来就是渐变/剪影，位图只作叠加纹理），版式不塌。 |
| 字体加载失败 | 回落 `system-ui`；行高锁 px；齿孔/虚线用 gradient，与字体无关。 |
| JS 未执行 | `noscript` 保留文案，并追加「三组默认值：10 分钟 / 还可以 / 跳过」。 |
| 离线 | 主按钮 `aria-disabled`，票根位置换「现在没网，等会儿再出票」；三组仍可改并写入本地。 |
| 存储 503 | DEGRADED 灰条「本次不保存记录」，记忆/反馈入口隐藏，播报一次，不弹窗。 |

对比度底线（实测）：票头与标题 `#1b2334` / 纸 14.8:1；正文 `#5a5f70` / 纸 5.99:1；纸内橙 `#b8480c` / 纸 4.98:1；选中项纸白字 / 墨底 15.45:1；未选中 `#1b2334` / `#F4EFE3` 13.69:1。`#ff8a50` 与 `#e0b33a` **只许出现在纸外**（夜色、光晕、黄线）。

已知取舍：未选中控件用「凹槽填充 + 字重」承担状态差异，1px 收边不承担识别职责，因此不满足「3:1 图形对比」这一条，但满足「不只靠颜色」——若做正式无障碍审计，需在此注明。

## 10. 风险与取舍

| # | 风险 | 缓解 |
| --- | --- | --- |
| 1 | 一屏一问 → 首次多两次点击 | 场景第一位是「跳过」；回访「用上次的条件」一键填满（1 次点击出票） |
| 2 | 折叠动画 → 高度跳动、焦点迷路 | 折叠用 `grid-template-rows 0fr→1fr`（不写死高度），选中后焦点显式移到下一格第一个选项 |
| 3 | 浅色把火车洗白 | 换清晨底图而不是提亮夜色；遮罩只压左侧文字区，列车侧 ≤0.26 |
| 4 | 默认值被当成用户选择 → 反馈数据污染 | 用 `touched` 标记区分「默认直接出票」的样本 |
| 5 | 票随内容变高 → 首屏被推下去 | 票宽固定 460、展开态约 440，1440×900 内始终一屏；只有窄屏才允许滚动 |
| 6 | 半透明纸台 + 电影感底图 → 文字对比度失控 | alpha 硬下限 .92 + 下缘柔化阴影 + 最亮帧实测；只允许提高 alpha，不允许改票内字色 |
| 7 | 「关于与数据」从页脚移到页首 → 少数人找不到记忆入口 | 小票根图标 + 首访一次性气泡（与 `whynot-guide` 共用键）+ 完整 aria-label + ≥340 宽保留页脚第二入口 |
| 8 | 窄屏票卡 100% 宽 → 选项挤成一行 | ≤480 选项改单列；场景 5 项在 ≤480 改 2 列 + 「跳过」独占一行 |
| 9 | 位图底图变重 → 首屏慢 | AVIF + `fetchpriority=high` + 底图尺寸按 `srcset` 下发；先给 1x，2x 仅在高 DPR 取 |
| 10 | 三套氛围维护成本 | 先上昼/夜两张，黄昏用调色层；三套作为 P2 |
