## 2. 功能实现

### 2.1 反馈与换卡

- state.seq 随成功换卡递增；反馈发起捕获 seq + cardId。
- 成功、失败回滚、finally 解锁均检查归属，旧响应无权覆盖或解锁新卡。
- 反馈在途仍能换卡；新卡到达时复位反馈锁与非法反馈次数。
- 新推荐失败时保留当前旧卡状态，而非盲目恢复过时的对象快照。
- 同一种偏好重复点击不提交；完成不可撤销。
- 乐观 UI 与服务端权威响应不一致时重新渲染；相同时避免额外重建焦点节点。

### 2.2 条件快照

- 主按钮在任何 await 前复制 {budget, energy, scene}，会话初始化也不能推迟快照。
- 当前卡的快照仅随成功的新卡一起提交，失败保留旧卡快照。
- 请求中或响应后改条件均不自动生成；不一致时显示「按 N 分钟生成」与「按新条件再来一条」。
- 「再试一次」使用失败请求的快照；「按新条件再来一条」读取当前选择。
- 服务端返回条件只作一致性校验；不一致仅记录固定 warn 字符串，不打印用户内容，并隐藏条件标注。
- category 缺失、未知或 toString 等非白名单字符串均安全降级。

### 2.3 错误与恢复

- 区分 network_error、25 秒 timeout、invalid_response、SESSION_REQUIRED、NOT_FOUND、INVALID_FEEDBACK、STORAGE_UNAVAILABLE 和非法请求错误。
- 超时覆盖 fetch 和响应体读取阶段。
- 每次请求最多一次会话重建重放、一次存储错误重试（800ms）；两种错误轮流出现也不会无限循环。
- 保持后端原错误契约，409 在前端映射为存储不可用；未采用规格中的可选后端归一化修改。
- NOT_FOUND 不重试旧卡，结果区移除旧卡并只给「换一个」。
- INVALID_FEEDBACK 允许一次手动再试，再失败不继续提交。
- INVALID_CONTEXT / JSON_REQUIRED / INVALID_BODY 不给无效重试循环。
- 网络失败保留选择和旧卡；离线禁用换卡；网络恢复就地提示，不自动请求。

### 2.4 加载、焦点、播报

- 骨架 0 秒「正在找建议」、8 秒「还在找，再等一下」；finally 清除计时器。
- 完整结果容器不再是 live region；固定 polite status 只承担短句，反馈用独立可见 status。
- 骨架视觉占位 aria-hidden，0 秒由独立 status 播报；8 秒不新增播报，符合工程裁决。
- 生成失败仅提示文本节点 role=alert，旧卡不会跟随整块播报；离线/恢复用 status。
- 首屏不抢焦点；生成时焦点临时落结果容器，主入口成功后到标题，换卡成功后回换卡按钮。
- 用户在等待中已经移到条件区时，不抢回焦点。
- 主入口标题的可访问名含标题与耗时，不再同时发重复的 polite 新卡消息；换卡入口使用短 status。
- 反馈焦点保持；完成节点替换后有 tabindex=-1 的状态落点；折叠关闭回入口。
- 反馈使用 aria-disabled + 逻辑守卫而非 native disabled，保留键盘焦点；主按钮/离线换卡用 native disabled。
