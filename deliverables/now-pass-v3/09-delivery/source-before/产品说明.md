# WhyNot 首版产品说明

WhyNot 帮处在碎片时间里的大学生选一件现在就能做的事。用户选好时间和精力，可以再补一个场景，点一下就得到一条建议，知道先做什么、大约要多久。

## 为什么做

刚下课，在食堂等饭，还有十分钟。人有点累，也没想好要做什么，手已经点开了短视频。WhyNot 想在这一刻多给人一个选择。这个选择可以是看点新鲜事，也可以是安心刷一会儿视频，或者干脆放空。首版要验证的是，用户能否很快找到一件自己愿意开始的小事。

## 用户怎么用

当前 P0 已有可本地运行的前后端，包含主题、关于、分享与安装资源。公网交付仍需另行授权与验收。

1. 打开 WhyNot，直接进入「此刻」页，不需要注册；本地入口见 [README](README.md#本地开发与验收)。
2. 默认「10 分钟」「还可以」，场景可跳过；按当下情况调整时间、精力，愿意的话再补场景。
3. 点「给我一个建议」。页面显示一张卡片，写清行动、第一步和预计耗时。
4. 想试就放下手机去做。不合适就点「换一个」，按当前表单条件生成；也可以点「喜欢」「不喜欢」，做完后点「已完成」，再按需分享。

## 一次真实的体验

用户选了「10 分钟」「有点累」「等饭／排队」。即使还有十分钟，一件两分钟就能结束的事也合适。

> **等饭时，给眼睛放两分钟假**　约 2 分钟  
> 第一步：把手机放低，看看远处。  
> 找一处看着舒服的颜色，让目光停一会儿。轮到你时就收尾，安心吃饭。

点「换一个」后，可以得到「听听食堂里的两种声音」。两条建议都能随时停下，也都无需离开队伍。

## 页面与交互

只有「此刻」主页面与页脚折叠的「关于与主题」，没有「今日」页或历史列表。

| 位置 | P0／B4 行为 |
| --- | --- |
| 此刻 | 时间单选「3、5、10、15 分钟」，默认 10；精力单选「有点累、还可以、精神好」，默认还可以（steady）。场景默认跳过，可选「等饭／排队、在桌前、在路上、在家／宿舍」。修改条件不自动提交。 |
| 建议卡 | 一次显示一个行动，标题说清做什么，旁边标预计耗时，下一行直接给第一步。类别只作轻量提示，缺失或未知时仅隐藏类别，卡片仍可用。 |
| 换一个 | 使用当前表单条件；若条件已改，提示「按新条件再来一条」。新卡片有独立编号，旧反馈不变；换一个只请求推荐，绝不提交反馈。 |
| 反馈 | 「喜欢」「不喜欢」可改选，以最后选择为准，不是再次点击取消。「已完成」独立、重复提交只生效一次，成功后不可撤销。反馈失败会提示并恢复原状态，旧卡的延迟响应不能覆盖新卡。 |
| 等待与失败 | 生成时显示「正在找建议」，防止重复生成，仍可修改表单。失败保留条件和旧卡；「再试一次」重放失败请求的原始快照，而非当前新条件。网络恢复不自动提交。 |
| 关于与主题（B4） | 页脚展开后说明产品及数据用途，提供跟随系统／浅色／深色。浅色／深色分别以 `light`／`dark` 存于 `whynot-theme`，跟随系统则移除覆盖值，存储读写失败时静默回到跟随系统。 |
| 分享（B4） | 仅已完成卡片提供入口。原生分享不可用或失败时依次尝试 Clipboard、`execCommand`，最后提供可选中的文本供手动复制。用户取消原生分享时静默结束，不触发后续复制；分享本身不提交反馈。 |

分享链接只使用 `location.origin + location.pathname`，不携带 query、hash、建议编号、session token 或反馈信息；接收者打开后自行选择条件，不是访问原用户的建议记录。

安装相关仅补 manifest、Apple 180px 图标及 192／512px 安装图标。是否能添加到主屏幕取决于浏览器，不承诺自动安装。没有 service worker，也不支持离线重新打开；只有已经打开的页面可在断网后继续看旧卡片，不能离线生成建议。

## 推荐怎么选

- **时间是上限。** 包含准备在内的预计耗时应在预算内。只有 3 分钟时，第一步就能在原地完成；避开需要下载、查教程或准备材料的活动。
- **场景决定什么方便做。** 排队时要听得到叫号，在路上时要先确保可以安全停留。跳过场景时，给出无需假定身边有窗户、桌子或其他物品的建议。
- **精力决定行动的难度。** 「有点累」可以放空或休息；「精神好」可以观察一个设计、尝试一个小创作。文案用邀请的口吻，用户可以随时结束。
- **反馈只影响适合当下的候选建议。** 例如用户喜欢过「观察身边的小设计」，下次场景和精力合适时可优先推荐同类。只有明确点了「不喜欢」才记负向反馈。
- **模型失败有兜底。** 服务端校验行动、第一步、耗时和类别；模型每次调用超时 7 秒、最多尝试 2 次。未配置密钥、模型失败或输出无效时，从适合当前条件的内置建议中选一条；网络或存储失败仍需明确报错，不能保证离线生成。密钥只由服务端保管。

## 数据与接口边界

只按功能需要保存匿名会话、推荐条件、建议和反馈，不接入定位、日历或健康数据，不提供兴趣输入或兴趣追踪。模型可参考当前条件、近期建议标题和反馈类别；这些内容与密钥、模型原始响应不得写入日志。

浏览器保存 `whynot-session`（匿名 token）、`whynot-guide`（引导是否看过）及 B4 的 `whynot-theme`（主题）。服务端按 token 摘要确认归属，校验输入，并以数据库约束及条件更新保持完成记录幂等。匿名会话不是登录账号，也不承诺跨设备同步。

当前 Functions 基址为 `/functions/v1/app`：三个业务端点是 `POST /api/session`、`POST /api/recommendations`、`POST /api/recommendations/:id/feedback`，另有 `GET /api/health`，没有历史查询端点。会话先取 token，再通过 `x-whynot-session` 请求头携带；前端虽使用同源 credentials，但当前网关不转发应用 cookie，归属不靠 cookie。

卡片增量字段 `category` 为 `rest`／`observe`／`listen`／`tidy`／`explore`；旧响应缺失、空值或未知类别仅隐藏类别标记。完整请求、响应和错误契约见 [README](README.md#当前-api-契约)。旧 `app.py` 才使用 HttpOnly cookie、直接 `/api/*` 和 `/api/history`，与当前共享前端不兼容，不是当前联调入口。

## 验收目标（不代表已经通过）

本地运行 `node dev/server.mjs 8765`；API 用 `node dev/acceptance.mjs`，模型路径另开 `node dev/fake-model.mjs`（8766）后运行 `node dev/acceptance-model.mjs`。前两类验收支持 `BASE` 覆盖本地服务地址。`dev/acceptance-ui.mjs` 在浏览器运行，覆盖现有状态、时序和布局分组；具体步骤见 README。

| 验收场景 | 通过条件 |
| --- | --- |
| 只有 3 分钟，精力低 | 无论填写或跳过场景，都只返回一条低负担建议，含明确第一步，预计耗时最多 3 分钟。 |
| 改条件、换建议与重试 | 改条件不发请求；换一个用当前表单且不发反馈；失败重试使用原始快照。 |
| 反馈归属与幂等 | 喜欢／不喜欢可改选；已完成重复提交仅生效一次且不能撤销；旧卡响应不影响新卡。 |
| 模型不可用 | 从实际推荐入口验证有限等待后的合规兜底，以及无效输出和上游错误。 |
| 错误输入或他人的建议编号 | 服务端返回明确错误，已有记录保持正确。 |
| B4 主题与分享 | 主题持久化及存储失败降级正确；完成前不提供分享；取消无提示；各复制降级可用，链接无敏感参数。 |
| 离线与安装资源 | manifest 和图标可访问；已打开页面保留旧卡，离线生成被阻止；不声称可离线重新打开或自动安装。 |
| 公开访问（后续待授权） | 用真实手机无痕窗口打开最终 Qoder Sites 地址，无须开发者账号，走通完整体验。 |

云端／公网验收、真实手机、有声屏幕阅读器测试和性能基准尚未验证。gzip 最终上限按 **16 KiB（16384 B）** 统计整个 `web/`（包含 manifest 与安装图标），原四项资源同时对照初定的 14 KiB；原始体积上限未被放宽。实测数据、超限与人工未验项见 [B4 阶段日志](deliverables/b4-wrapup/B4-关于主题与收尾日志.md)。
